# Looplet Accounting

Job-costed AP/AR for trades businesses. Multi-tenant from day 1.
Supabase-native. Xero-as-printer-driver.

The headline feature: **per-job true profit** ("what's really yours").
Replace Xero as the destination, treat Xero today as one of several
output channels.

---

## Quick start

```bash
# 1. Install dependencies
npm install

# 2. Configure environment
cp .env.example .env.local
# Fill in VITE_SUPABASE_ANON_KEY (from Supabase dashboard → Settings → API)

# 3. Generate types from the live schema
npm run supabase:link        # one-time, links to dxoikltymmknxqpkpyhi
npm run supabase:types       # writes src/lib/database.types.ts

# 4. Run dev server
npm run dev                  # http://localhost:5173
```

Sign up creates a new auth user. Tenant infrastructure (organizations,
memberships) is in the schema but the signup-flow → entity-creation glue
lands in Phase 1 of the roadmap.

## Architectural commitments (locked)

See `docs/ROADMAP.md` for full detail. Headline:

- **Multi-tenant from line 1.** RLS-enforced. Cross-tenant data leak = P0
  deploy-block.
- **Looplet is source of truth.** Xero, MYOB, etc. are output channels —
  swappable, not authoritative.
- **AP push to Xero = single shot on bill attachment to a job.** No
  reconciliation drift.
- **Money as `BIGINT` cents, `TIMESTAMPTZ` everywhere, immutable audit
  log via Postgres triggers, period locking from day 1.**
- **Org structure copied from Looplet CRM** — Phase 8 connection becomes
  a name match.

## How this relates to Loopletnumero

Loopletnumero (`C:\Users\User\Documents\GitHub\Loopletnumero`) is the
Mongo prototype that proved the OCR + Xero pipeline end-to-end. It is
**not** the production system. Its services (`services/ocr/*`,
`services/po/poMatching.ts`, `services/pcr/`,
`services/accounting/XeroAdapter.ts`) get **ported** into this repo
during Phase 3 of the roadmap, then Loopletnumero is retired before any
AFGC production data touches it.
